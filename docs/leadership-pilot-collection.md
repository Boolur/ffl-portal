# Leadership Pilot collection

The Pilot worker reads Arive using the saved branch connection. It writes loan facts, tracker dates, the projected filing location, application details and note history to private Pilot tables. The standard workflow continues to use its own loan, task, payroll and notification tables. An enrolled leadership test package must match the imported loan, submission request, document package and registered Arive GUID before the Pilot collector can read it.

The production scheduler calls `/api/internal/arive/leadership-pilot` every minute. The endpoint requires the scheduler secret. Collection starts disabled. Admin III controls enablement and cohort size. Turning the display on opens the viewer's Pilot workspace. Each batch checks the operator control before leasing work, and checks its generation again before publishing. Pausing collection preserves the last complete projection.

A collection verifies the borrower, originator, numeric loan number and permanent GUID before fetching trackers and all note pages. It repeats the details read to detect a file edited mid-refresh. It checks the connection revision and loan identity again before saving. Two file leases and the shared transport protect against overlapping work across instances. A complete read takes at least four provider requests, plus exact search for a new link, authentication when needed and additional note pages. A partial read keeps the previous complete result. An identity exception goes to review.

The worker checks one page of up to 100 recently updated Arive loans at most once per minute. A newer provider modification time can prioritize a verified number/GUID pair for a complete read. A missing loan in that page, an absent timestamp, or an unavailable hint feed cannot skip the ordinary sweep. That sweep reads trackers and notes even when the details timestamp did not change. Each worker wave reserves capacity for oldest-due files alongside manual, watched or hinted files.

Arive's documented change events include stage, dates, archives and selected trackers. The branch reference does not establish callback authentication or a validated payload contract, or promise delivery for notes, rate locks, and every tracker. The worker uses authenticated GETs and ordered-list hints. It makes no subscription or outbound loan changes.

The normal due interval is 30 seconds after a successful active-file read, 10 seconds for a watched file, and one hour for quiet funded/archived files. These intervals make a file eligible for another read. Actual freshness includes provider visibility, the next worker opportunity, existing work, API latency, and any provider cooldown. A viewer's request joins the same collection queue. Report a measured under-one-minute result only when a timed source change is matched to the same verified loan revision displayed in the Pilot. Count each empty, stale, unverified, or provider-blocked file separately from verified coverage.
